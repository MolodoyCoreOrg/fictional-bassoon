# 🎵 GG_Loader Bot - Музыкальный Telegram Бот

Бот для загрузки и обработки музыки в Telegram с поддержкой обложек, метаданных и скачивания с музыкальных площадок.

## 🚀 Возможности бота

### Основные функции:
- **🫦 Добавление обложки к MP3** - загрузите свой MP3 файл и квадратную картинку, бот добавит обложку
- **🟢 Редактирование метаданных** - укажите автора и название трека (вместо "неизвестно")
- **😵 Красивое оформление** - отправка файла с обложкой и информацией
- **📥 Загрузка с площадок** - скачивание музыки из VK, Яндекс Музыки, YouTube и других источников
- **🔍 Inline-режим** - SoundCloud/VK/YouTube, личная история и мгновенная отправка аудио без кнопки загрузки

## 📋 Требования

- Python 3.9+
- FFmpeg (для обработки аудио)
- Telegram Bot Token

## 🛠 Установка

### Вариант 1: Локальный запуск

1. **Клонируйте репозиторий:**
```bash
cd /workspace/music_bot
```

2. **Создайте виртуальное окружение:**
```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate  # Windows
```

3. **Установите зависимости:**
```bash
pip install -r requirements.txt
```

4. **Настройте переменные окружения:**
```bash
cp .env.example .env
# Отредактируйте .env и добавьте ваш токен
```

5. **Запустите бота:**
```bash
python bot.py
```

### Вариант 2: Docker

1. **Соберите образ:**
```bash
docker build -t gg_loader_bot .
```

2. **Запустите контейнер:**
```bash
docker run -d \
  --name gg_loader \
  -p 127.0.0.1:8080:8080 \
  -e BOT_TOKEN="ваш_токен" \
  -v $(pwd)/temp:/app/temp \
  -v $(pwd)/data:/app/data \
  gg_loader_bot
```

### Вариант 3: systemd сервис (для сервера)

1. **Скопируйте файл сервиса:**
```bash
sudo cp gg_loader.service /etc/systemd/system/
```

2. **Настройте пути в файле сервиса**

3. **Запустите сервис:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable gg_loader
sudo systemctl start gg_loader
```

### Ссылки на Spotify, Apple Music, VK Audio и Яндекс Музыку

Стриминговые каталоги часто не отдают исходный аудиофайл через `yt-dlp`, а
часть треков защищена DRM. Бот сначала получает точные название и исполнителя:
для Яндекс Музыки — по ID трека через каталожный API, для VK Audio — через
`audio.getById` при наличии `VK_ACCESS_TOKEN`, затем через экстрактор и
публичные метаданные страницы.

Если оригинальный поток недоступен, бот ищет доступную версию в настроенных
источниках, но скачивает её только при достаточно точном совпадении названия и
исполнителя. Служебные подписи вроде «Яндекс Музыка / собираем музыку для вас»
и слабые совпадения отклоняются: вместо случайной песни пользователь получает
понятную ошибку. Закрытые и DRM-защищённые треки требуют разрешённого токена,
cookies или поддержки площадки; обход защиты не выполняется.

### Если YouTube пишет «Sign in to confirm you’re not a bot»

Бот сначала пробует прямую загрузку. Если площадка возвращает 403 либо только
каталожную страницу, бот извлекает название/исполнителя и перебирает несколько
совпадений в SoundCloud, VK и YouTube. Порядок задаётся через
`AUDIO_SEARCH_SOURCES=scsearch,vksearch,ytsearch`, число проверяемых результатов
каждого источника — через `AUDIO_FALLBACK_CANDIDATES=3`, а минимальная
уверенность совпадения — через `AUDIO_FALLBACK_MIN_MATCH=0.78`. Для
`vksearch` и точного разрешения VK Audio нужен `VK_ACCESS_TOKEN`; без него
источник автоматически пропускается, а бот не подменяет трек случайным.

Для прямых YouTube-ссылок экспортируйте свежие cookies только из отдельного
приватного сеанса в Netscape `cookies.txt`, положите файл рядом с `bot.py`
или передайте путь через `COOKIES_FILE`. Не коммитьте этот файл.

На серверных IP одного cookies-файла часто недостаточно. Рекомендуемая схема
yt-dlp — динамический PO-token provider. Запустите sidecar:

```bash
docker run --name bgutil-provider -d --init -p 4416:4416 \
  brainicism/bgutil-ytdlp-pot-provider:1.3.2
```

и добавьте в `.env`:

```env
YOUTUBE_POT_PROVIDER_URL="http://127.0.0.1:4416"
YOUTUBE_PLAYER_CLIENT="mweb"
YTDLP_JS_RUNTIME="deno"
```

Для Docker эти настройки уже включены в `compose.yaml`: создайте `.env` с
`BOT_TOKEN`, затем запустите `docker compose up -d --build`. Compose поднимет
бота и PO-token provider в общей сети. При запуске через systemd установите
Deno >= 2.3; альтернативный Node.js должен быть версии 22 или новее.

При заданном `YOUTUBE_POT_PROVIDER_URL` бот автоматически выбирает клиент
`mweb`. Если обычная загрузка видео возвращает 403, бот заново получает свежие
ссылки и пробует HLS-профиль `web_safari`, затем cookie-free профиль
`android_vr`. Для сайтов с Cloudflare устанавливается `curl_cffi` и по
умолчанию применяется `YTDLP_IMPERSONATE=chrome`.

### Настройка прямой отправки в inline-режиме

Telegram принимает новый inline-аудиотрек только по публичному URL MP3. Бот
поднимает встроенный media gateway, который скачивает найденный трек,
конвертирует его в MP3 и отдаёт Telegram. Укажите публичный HTTPS URL и
направьте этот путь reverse proxy на порт приложения:

```env
INLINE_MEDIA_BASE_URL="https://bot.example.com"
INLINE_MEDIA_HOST="0.0.0.0"
INLINE_MEDIA_PORT="8080"
INLINE_MEDIA_CACHE_DIR="/app/temp/inline_media_cache"
TRACK_HISTORY_DB="/app/data/track_history.sqlite3"
```

Например, для nginx достаточно проксировать `/inline/audio/` на
`http://127.0.0.1:8080`. Без `INLINE_MEDIA_BASE_URL` ранее сохранённые песни
продолжат работать, но новые результаты из внешних каталогов не смогут
вставляться в чат напрямую.

Для поиска VK Музыки добавьте пользовательский токен с доступом к методу
`audio.search`:

```env
AUDIO_SEARCH_SOURCES="scsearch,vksearch,ytsearch"
AUDIO_FALLBACK_CANDIDATES="3"
AUDIO_FALLBACK_MIN_MATCH="0.78"
VK_ACCESS_TOKEN="..."
VK_API_VERSION="5.199"
```

История хранит Telegram `file_id`, а не MP3-файлы, и показывается только
владельцу. Новые загрузки добавляются автоматически и выводятся от самых свежих
к более ранним. Существовавшие до установки этой версии сообщения Telegram API
восстановить не позволяет.

Чтобы выбранные новые inline-треки гарантированно попадали в историю, включите
inline feedback для бота в @BotFather и установите 100%. Необязательно укажите
`INLINE_STORAGE_CHAT_ID` закрытого канала, где бот сможет сохранять полученные
`file_id`; добавьте бота в этот канал с правом публикации.

## 🐛 Решение проблем

### Бот не запускается
- Проверьте токен в .env
- Убедитесь, что установлены все зависимости
- Проверьте логи ошибок

### Ошибки при обработке аудио
- Убедитесь, что FFmpeg установлен: `ffmpeg -version`
- Проверьте права доступа к папке temp

### Inline-режим не работает
- Включите inline-режим в @BotFather
- Установите username бота как default helper

### Видео больше 50 МБ и актуальная авторизация YouTube

Облачный Bot API принимает загружаемые ботом видео и документы только до 50 МБ.
Для файлов до 2000 МБ запустите собственный `telegram-bot-api` с `--local`
и настройте:

```env
TELEGRAM_API_BASE_URL="http://127.0.0.1:8081"
TELEGRAM_LOCAL_FILE_MODE="true"
TELEGRAM_MAX_UPLOAD_MB="2000"
TELEGRAM_UPLOAD_TIMEOUT_SECONDS="7200"
```

Для YouTube используйте свежий Netscape `cookies.txt` через `COOKIES_FILE`.
Статический `YOUTUBE_PO_TOKEN` оставлен для совместимости, но YouTube привязывает
новые токены к видео, поэтому для продакшена используйте динамический provider:

```env
YTDLP_JS_RUNTIME="deno"
YOUTUBE_PLAYER_CLIENT="mweb"
YOUTUBE_POT_PROVIDER_URL="http://127.0.0.1:4416"
```

Без `TELEGRAM_API_BASE_URL` бот автоматически применяет облачный лимит 50 МБ;
с локальным API — 2000 МБ. Включайте `TELEGRAM_LOCAL_FILE_MODE=true` только
когда бот и `telegram-bot-api` видят каталог `temp` по одному абсолютному пути
(например, через общий Docker volume). Тогда файл передаётся серверу как
`file://` и не загружается повторно по HTTP. Если общей файловой системы нет,
оставьте `false`: бот загрузит видео через multipart с увеличенным тайм-аутом.
